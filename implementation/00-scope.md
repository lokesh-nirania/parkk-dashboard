# Scope

## In

**The front half of the lifecycle, working.**

- **Quotation** — a quote is a real project from the moment it is raised, with
  estimated dates and an estimated crew size, all of it revisable while the
  quote is open — including the scope, which is the paragraph the job is priced on.
- **Confirmation** — the gate that turns an estimate into a commitment. The
  agreed dates and crew size become a baseline that is never overwritten.
- **Planning** — six workstreams running in parallel, each holding tasks, plus a
  crew list of seats. A seventh workstream can be added to any project from the UI.
- **The crew list as seats** — added, filled, released, mid-job. Filling a seat
  writes that person's obligations; releasing one keeps the record and stops the
  work counting.
- **People** — Parkk staff as records. Managers are assignable today and become
  logins later.
- **The derived screens that justify the model** — the board, the expiry radar,
  logistics across projects, and a trail that answers who moved this, when and why.

## Out, deliberately

Say these out loud in a demo so they do not read as gaps.

| Out | Why |
|---|---|
| Manager logins | Managers exist as records and are assignable. Scoping what they see is a policy change, and it comes first in [PLAN.md](../PLAN.md). |
| Execution — daily reports, obligations | A different rhythm: recurring rather than one-shot. The stage and the substage machinery already generalise to it. |
| Invoicing and cost tracking | Projects carry a quote value so the number is on the record. Nothing is derived from it. |
| Blockers as first-class records | `blocked` exists as a status. A blocker with an age and a cost impact is a bigger object. |
| Warehouse inventory | Never in scope. Logistics tracks what a project needs and whether it arrived — never what sits on a shelf. |
| Attachments | A visa is a PDF in somebody's inbox. Storage is easy; retention policy on passport scans is not. |
| Bulk edit and CSV import | Twelve visas on one phone call is twelve clicks today. It matters the day this holds a real project. |

## The rule the whole thing is built on

Nothing is stored that can be derived, and nothing is derived that should be
remembered. A rollup is always a view — so the board and the project page cannot
disagree. A change is always a row in the trail — so the current state can be
wrong about the past and the record still is not.
